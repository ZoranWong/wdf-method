# Change Proposal Template

```
Change ID: CHG-YYYY-NNN (e.g., CHG-2026-001)
Proposed: YYYY-MM-DD
Author: <name>
Status: DRAFT | REVIEW | APPROVED | IMPLEMENTED | REJECTED
```

## 1. 摘要

**问题：** 一句话描述当前的问题或机会

**方案：** 一句话描述提议的变更

**影响：** 低 | 中 | 高

---

## 2. 背景与动机

描述为什么需要这个变更。包括：
- 发现的问题（Bug、性能、安全、可用性...）
- 业务机会
- 技术债累积
- 外部依赖变更

---

## 3. 规范差异 (Spec Delta)

### 3.1 修改前的规范

```

...
```

### 3.2 修改后的规范
描述变更后的规范。

```

```

### 3.3 兼容性分析
- [ ] 完全向后兼容（仅新增）
- [ ] 部分不兼容（有废弃、行为变更）
- [ ] 破坏性变更（需要迁移脚本）

**迁移策略：** （如需要）

描述如何在出现问题时回滚此变更。
