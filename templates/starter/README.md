# WDF Starter Template

A minimal scaffold for a standard web application: TypeScript backend +
TypeScript frontend, separated dev mode. Use this when you want a clean
starting point without committing to the full todo-app example.

## What's Inside

| Path | Purpose |
|------|---------|
| `wdf.toml` | Project config (you fill in `<PROJECT_NAME>`, version) |
| `customize.toml` | Framework-level customization (overrides `wdf-method/customize.toml`) |
| `constitution.yaml` | Project-level non-negotiable rules |
| `.claude/agents/wdf-starter.md` | Reference agent for this template |
| `backend/` | Empty TypeScript backend skeleton (Express + Zod) |
| `frontend/` | Empty TypeScript frontend skeleton (Vite + React) |
| `tasks.md` | Cross-session continuity载体 (Claude writes, wdf reads) |

## Usage

```bash
# Copy the template into a new project location
cp -r wdf-method/templates/starter /path/to/my-project
cd /path/to/my-project

# Initialize WDF state files (creates _wdf_output/, status/, etc.)
wdf init "my-project description"

# Start the workflow
wdf start
```

Alternatively, use it as a reference while running `wdf init` interactively —
that path generates a comparable scaffold but lets the wizard drive
configuration choices.

## Choices Locked In

This template takes a position on a few things, so you don't have to:

- **TypeScript strict** everywhere (BE + FE)
- **Separate dev mode** (`separated`, not `full_stack`) — gives you track
  isolation until integration
- **Parallel triage** for Phase 3 stories
- **5-retry pipeline** + **24h escalation hold** (the framework defaults)
- **Express + Zod** for the backend (not Fastify, not NestJS)
- **Vite + React** for the frontend (not Next.js)

Override any of these in your project's `wdf.toml` after copying.

## Not In This Template

- No example stories — see `examples/todo-app/_wdf_output/stories/` for shape
- No Phase 1-3 artefacts — those are generated by Claude during the workflow
- No tests beyond the smoke check — bring your own testing strategy
- No database setup — bring your own migration tooling
